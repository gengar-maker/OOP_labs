## 1. Цель работы

Научиться точно читать синтаксис создания объекта, а не воспринимать `()`, `{}` и `=` как взаимозаменяемое оформление.

После выполнения работы вы сможете:

1. отличать конструктор от формы инициализации;
2. объяснять разницу между `T object;`, `T object{}`,
   `T object(args)` и `T object{args}`;
3. учитывать `explicit` при прямой и копирующей инициализации;
4. находить сужающие преобразования;
5. распознавать запись `T object()`, которая объявляет функцию вместо объекта;
6. передавать начальные значения полям простой структуры в порядке их объявления;
7. задавать начальные значения по именам полей с помощью записи `.field = value`;
8. отличать инициализацию от присваивания уже существующему объекту;
9. выбирать между открытой структурой конфигурации и классом, который защищает своё состояние.

## 2. Предварительные знания

Нужно знать:

- различия `struct` и `class`;
- назначение конструктора;
- уровни доступа `public` и `private`;
- список инициализации членов конструктора;
- назначение `explicit`.

## 3. Нужно понимать разницу: конструктор и форма инициализации

Конструктор — функция класса, определяющая допустимые способы создания его объектов:

~~~cpp
class Battery {
public:
    explicit Battery(int charge);
};
~~~

Форма инициализации — синтаксис в месте создания объекта:

~~~cpp
Battery first(80);
Battery second{80};
~~~

Обе записи могут выбрать один конструктор, но правила выбора и допустимые преобразования у них уже будут отличаться.

> [!warning] Не путайте два списка
> `Battery value{80};` используется непосредственно в месте создания объекта. Фигурные скобки передают значение `80` подходящему конструктору. Официальное название такой формы инициализации— **list-initialization**.
>
> `Battery(int value) : charge_(value) {}` находится внутри определения конструктора. Часть после `:` задаёт начальные значения полей до выполнения тела `{ ... }`. Это уже знакомый **список инициализации членов**, или **member initializer list**.
>
> Похожее слово «инициализация» в данному случае относится к разным вещам: первая создаёт объект, вторая описывает создание его полей изнутри конструктора.

## 4. Основные формы инициализации

Сначала остановимся на условных обозначениях, которые используются ниже:

```cpp
T object(args);
```

- `T` — некоторый тип, например `int`, `Point` или `Battery`;
- `object` — имя создаваемой переменной;
- `args` — значения, передаваемые при создании;
- `value` — одно значение, из которого пытаются создать объект.

Например, в записи `Battery battery(80);` типом `T` является `Battery`, именем объекта — `battery`, а аргументом — число `80`.

Важно: таблица описывает не шесть разных видов объектов. Это шесть способов записать **создание и начальную настройку одного объекта**. Разные скобки включают разные правила языка.

| Запись               | Что это означает по сути                                                             | Что произойдёт                                                                                                                                                                         |
| -------------------- | ------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `T object;`          | Создать объект, не указывая начальное значение явно                                  | Для класса вызывается конструктор без аргументов. Переменная встроенного типа, объявленная без инициализатора, например `int number;`, не имеет значения, которое можно было бы читать |
| `T object{};`        | Создать объект без аргументов и явно попросить корректное пустое начальное состояние | Для класса вызывается конструктор без аргументов. `int` получает `0`, `bool` — `false`, а поля простой структуры получают свои значения по умолчанию или нули                          |
| `T object(args);`    | Создать объект и передать аргументы в подходящий конструктор                         | Разрешены `explicit`-конструкторы и обычные преобразования аргументов. Например, `19.9` может неявно превратиться в `19`, если нужен `int`                                             |
| `T object{args};`    | Создать объект с аргументами через фигурные скобки                                   | Для класса выбирается конструктор, а для простой структуры значения передаются её полям. Преобразования с возможной потерей данных запрещаются                                         |
| `T object = value;`  | Попросить компилятор неявно получить объект типа `T` из другого значения             | `explicit`-конструктор использовать нельзя. Эта форма нужна только тогда, когда неявное преобразование действительно является частью интерфейса типа                                   |
| `T object = {args};` | Создать объект через список значений, но с записью через `=`                         | Потеря данных также запрещена. На начальном этапе обычно понятнее писать `T object{args};` без знака `=`                                                                               |
Далее каждый пункт еще рассмотрим подробнее.
### Быстрое практическое правило

- Для числа, флага или простой структуры без начальных данных используйте `{}`: `int count{};`, `Point origin{};`.
- Для класса с аргументами обычно начинайте с фигурных скобок: `Battery battery{80};`.
- Используйте `()` осознанно, если нужны именно правила круглых скобок.
- Формы через `=` применяйте тогда, когда действительно хотите разрешить неявное преобразование.

Официальные названия форм нужны для чтения справочников и сообщений компилятора. Они будут вводиться после того, как понятен смысл каждой записи.

## 5. Создание без скобок — значение явно не задано

~~~cpp
Battery battery;
int number;
~~~

Для класса компилятор пытается вызвать конструктор без аргументов. Такой конструктор называют **конструктором по умолчанию**, а форму `Battery battery;` — **default-initialization**.

Переменная встроенного типа `int number;` не получает заданного программой начального значения. Читать её до присваивания нельзя:

~~~cpp
int number;
// std::cout << number; // ошибка программы: number ещё не инициализирован

number = 10;            // теперь значение определено
std::cout << number;
~~~

## 6. Пустые фигурные скобки

~~~cpp
Battery battery{};
int number{};  // 0
Point point{}; // int-поля без других инициализаторов получают 0
~~~

Для класса выбирается доступный конструктор без аргументов. Для встроенного типа и простой структуры `{}` помогает избежать незаданного начального состояния.

В справочной литературе здесь встречаются названия **value-initialization** и **list-initialization**. На данном этапе важнее наблюдаемое поведение: `int number{};` создаёт число со значением `0`, а не «случайным» содержимым памяти.

Практическое правило: если нужен «пустой, но корректно инициализированный» объект, `{}` обычно выражает намерение яснее.

## 7. Круглые скобки — выбор конструктора с передачей его аргументов

~~~cpp
Battery first(80);
Battery second(19.9); // double преобразуется в int
~~~

Компилятор ищет конструктор, параметры которого подходят переданным аргументам. Такая форма официально называется **direct-initialization**.

В ней разрешено явно вызвать `explicit`-конструктор. Обычные преобразования аргументов также возможны, поэтому `19.9` может превратиться в `19` с потерей дробной части.

Тут можно попасть в ловушку:

~~~cpp
Battery first;    // объект
Battery second{}; // объект
Battery third();  // объявление функции third, возвращающей Battery
~~~

`Battery third();` не означает «создать батарею без аргументов». Это объявление функции `third`, которая ничего не принимает и возвращает `Battery`. Историческое название данной ситуации — **most vexing parse**.

Для создания объекта без аргументов используйте `Battery third;` или `Battery third{};`.

## 8. Фигурные скобки — создание объекта с защитой от потери точности

~~~cpp
Battery first{80};
// Battery second{19.9}; // ошибка: сужающее преобразование
~~~

Эта форма официально называется **direct-list-initialization**. Для класса она выбирает подходящий конструктор. Для простой структуры с открытыми полями значения могут быть переданы непосредственно её полям; такие типы разбираются в разделе 10.

Главное полезное свойство: фигурные скобки запрещают **сужающие преобразования** — преобразования, при которых значение может потерять часть информации. Поэтому `{}` часто помогает обнаружить ошибку раньше.

В англоязычной документации сужающее преобразование называется **narrowing conversion**. К типичным примерам относятся:

- `double` в `int`;
- слишком большое целое значение в меньший целый тип;
- целое значение в `float`, если оно не представимо точно;
- значение переменной целого типа в более узкий целый тип.

Некоторые константные выражения разрешены, если значение точно помещается в целевой тип.

> [!note] Конструкторы с initializer_list
> Если класс имеет подходящий конструктор с `std::initializer_list`, `{}` сначала рассматривает его. Поэтому `Type(1, 2)` и `Type{1, 2}` могут выбрать разные конструкторы. Подробная работа с `std::initializer_list` относится к теме контейнеров и перегрузки и будет рассмотрена позднее.

## 9. Создание через знак равенства и роль explicit

~~~cpp
class Battery {
public:
    explicit Battery(int charge);
};

Battery direct(80);       // разрешено
Battery directList{80};   // разрешено
// Battery implicit = 80; // ошибка из-за explicit
~~~

`Battery implicit = 80;` читается как просьба: «компилятор, сам преобразуй число `80` в объект `Battery`». Такая форма называется **copy-initialization**.

`explicit` не запрещает вызывать конструктор. Оно запрещает использовать его для подобного неявного преобразования, которое программист не выразил круглыми или фигурными скобками.

Слово `copy` в названии не означает, что обязательно будет создана лишняя копия. Это историческое название набора правил выбора конструктора.

## 10. Что такое агрегат

Рассмотрим простую структуру:

~~~cpp
struct Point {
    int x;
    int y;
};
~~~

Оба поля публичны, а собственного конструктора у `Point` нет. Поэтому значения можно передать прямо полям:

~~~cpp
Point point{10, 20}; // x = 10, y = 20
~~~

Тип, который язык C++ разрешает инициализировать непосредственно по его элементам, называется **агрегатом**. `Point` в этом примере — агрегат.

Для наших примеров C++20 используем рабочее правило: тип не должен иметь

- пользовательских или унаследованных конструкторов;
- приватных и защищённых нестатических полей;
- виртуальных функций;
- виртуальных, приватных или защищённых базовых классов.

Чаще агрегат записывают как `struct`, однако ключевое слово само по себе ничего не гарантирует. `class` с открытыми членами тоже может быть агрегатом, а `struct` с пользовательским конструктором — уже нет.

### 10.1 Что будет, если часть полей публичная, а часть приватная

Если у типа есть хотя бы одно приватное или защищённое нестатическое поле, в C++20 этот тип не является агрегатом. Значения из `{...}` уже нельзя передать непосредственно его полям:

~~~cpp
class Example {
public:
    int publicValue;

private:
    int privateValue;
};

// Example first{10, 20};            // ошибка: нет конструктора
//                                      // с двумя параметрами
// Example second{.publicValue = 10}; // ошибка: тип не агрегат
~~~

Наличие публичного поля не меняет результат: приватное поле делает весь тип неагрегатным. Запись `.publicValue = 10` внутри `{}` тоже не сработает, потому что инициализация по именам полей разрешена только для агрегатов.

Пустые фигурные скобки могут работать и для неагрегатного класса:

~~~cpp
Example object{};
~~~

В этом случае скобки не обходят `private` и не обращаются к полям напрямую. Компилятор вызывает доступный конструктор без аргументов. В примере выше такой конструктор неявно создаётся компилятором, а оба поля `int` получают `0`.

Чтобы передать значения неагрегатному классу, нужен публичный конструктор:

~~~cpp
class ConfiguredExample {
public:
    ConfiguredExample(int publicValue, int privateValue)
        : publicValue(publicValue),
          privateValue(privateValue) {}

    int publicValue;

private:
    int privateValue;
};

ConfiguredExample object{10, 20}; // вызывается конструктор
~~~

> [!important] Одинаковые скобки — разные механизмы
> `Point point{10, 20};` — значения идут непосредственно полям агрегата.
>
> `ConfiguredExample object{10, 20};` — вызывается конструктор.
>
> Если тип не агрегат и подходящего конструктора нет, компилятор сообщит об ошибке.

## 11. Значения полей в порядке их объявления

~~~cpp
Point first{10, 20};
Point second{};
~~~

Первое значение получает первое поле, второе — второе и так далее. В `Point first{10, 20};` число `10` попадает в `x`, а `20` — в `y`.

Такой способ называется **позиционной инициализацией агрегата**: смысл значения определяется его позицией внутри `{}`.

Пропущенные поля используют начальное значение, заданное прямо в объявлении поля. Если его нет, поле инициализируется пустыми фигурными скобками; например, `int` получает `0`.

Начиная с C++20 агрегат можно напрямую инициализировать круглыми скобками:

~~~cpp
Point third(30, 40); // C++20
~~~

Но формы не равнозначны. В частности, агрегатная инициализация через `()` не запрещает сужающие преобразования так, как это делает `{}`. Для объектов с публичными полями фигурные скобки обычно безопаснее.

## 12. Инициализация по именам полей: .field = value

Начиная с C++20 можно явно подписать, какое поле получает значение:

~~~cpp
struct WindowSettings {
    int width = 800;
    int height = 600;
    bool fullscreen = false;
};

int requestedWidth = 1280;

WindowSettings settings{
    .width = requestedWidth,
    .height = 720,
    .fullscreen = true
};
~~~

Имя после точки должно быть именем непосредственного нестатического поля агрегата. Справа от `=` находится обычное выражение: литерал, переменная, результат функции или создаваемый вложенный объект.

Официальное английское название такой записи — **designated initializer**, или именованный инициализатор.

### 12.1 Это не присваивание через точку

~~~cpp
WindowSettings first{.width = 1280}; // создание и инициализация

WindowSettings second{};             // сначала создание
second.width = 1280;                 // затем присваивание
~~~

В первом случае объект сразу начинает жизнь с заданным состоянием. Во втором поле уже существующего объекта изменяется после завершения инициализации.

### 12.2 Только агрегаты

~~~cpp
class Robot {
private:
    int energy_ = 100;
};

// Robot robot{.energy_ = 50}; // ошибка: Robot не агрегат
~~~

Инициализация по именам полей не обходит `private`. Если класс защищает инвариант, его нужно создавать через публичный конструктор.

### 12.3 Порядок полей обязателен

~~~cpp
WindowSettings correct{
    .width = 1280,
    .height = 720
};

// WindowSettings wrong{
//     .height = 720,
//     .width = 1280 // ошибка: вернуться к более раннему полю нельзя
// };
~~~

В C++ имена должны следовать порядку объявления полей. Поля можно пропускать, но нельзя возвращаться назад.

### 12.4 Что происходит с пропущенными полями

~~~cpp
WindowSettings settings{.height = 900};
~~~

`width` и `fullscreen` получают свои default member initializers. Если собственного инициализатора нет, пропущенный член инициализируется как пустым списком; пропущенный `int` получает `0`.

### 12.5 Ограничения C++20

Нельзя:

- смешивать позиционные и именованные элементы в одном списке;
- обозначать одно поле дважды;
- нарушать порядок объявления полей;
- обозначать член базового класса;
- использовать C-синтаксис `[3] = value` для массива;
- писать вложенный путь `.position.x = 10`.

Вложенный агрегат создаётся отдельным выражением:

~~~cpp
struct Entity {
    Point position;
    bool active = true;
};

Entity entity{
    .position = Point{10, 20},
    .active = false
};
~~~

## 13. Агрегат-конфигурация и класс с инвариантами

Именованные поля особенно удобны для открытых конфигураций:

~~~cpp
struct DeviceConfig {
    const char* name = "Unknown";
    int volume = 50;
    bool enabled = true;
};

DeviceConfig config{
    .name = "Speaker",
    .volume = 80
};
~~~

Но сама конфигурация не обязана обеспечивать сложный инвариант. Её можно передать конструктору класса, который проверит значения:

~~~cpp
class Device {
public:
    explicit Device(DeviceConfig config);

private:
    const char* name_;
    int volume_;
    bool enabled_;
};

Device device{config};
~~~

Таким образом роли разделяются:

- агрегат удобно собирает входные параметры;
- класс проверяет их и защищает собственное состояние.
